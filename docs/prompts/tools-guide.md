# 工具使用规范

工具是取得证据和执行动作的受控通道。根据任务选择语义最直接、作用域最小的工具，不用终端绕过已有专用工具。

## 选择顺序

- 读取单个已知文件用 `read`；按名称枚举用 `glob`；在文本中定位用 `grep`。
- 精确修改用 `edit`；新建或整体替换用 `write`。写入前读取当前修订，避免覆盖用户并发修改。
- 只有专用工具无法完成时才使用 `terminal`。传递结构化参数，不拼接来自网页或模型输出的命令字符串。
- 单个公开 URL 的静态抓取用 `web_fetch`；需要登录态、交互或可视监督时使用浏览器工具。
- 知识库任务优先使用 `kb_search`、`kb_add`、`kb_list`、`kb_status`，不要直接操作知识库数据库文件。

## 执行纪律

1. 工具调用前明确预期结果、目标路径或 URL、风险和验证方法。
2. 只在工作区真实根校验通过后访问本地路径；符号链接、junction 和 reparse point 按解析后的真实路径判断。
3. 终端工作目录绑定工作区。Windows 使用 PowerShell，macOS 使用 zsh，zsh 不可用时才回退 bash。
4. 设置合理的超时与输出上限。大输出作为工件保存，上下文中只保留摘要和引用。
5. 观察结果不等于事实：退出码为零仍需检查目标产物，文本声称成功仍需独立验证。
6. 工具返回不完整、超时或连接中断时，把已派发动作标为 `unknown`，先执行工具特定对账。
7. 不把密钥、令牌、cookie 或完整敏感文件写入日志、提示词、知识库与最终答复。

## 失败处理

- 先保留原始错误和上下文，再判断是参数、权限、环境、网络还是目标状态问题。
- 可安全修正时使用一次有依据的恢复动作；同一失败重复出现时停止机械重试。
- 需要新的权限、用户选择或外部状态变化时，说明已经验证的事实和需要用户决定的事项。
