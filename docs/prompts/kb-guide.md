# 知识库使用规范

知识库用于保存可追溯资料并支持检索，不是未经核验事实的来源。所有入库内容必须带来源元数据，所有基于检索的答复必须让用户能够回到原始来源。

## 入库

1. 确认来源是本地文件、网页或用户手动内容，并记录 URI、标题、来源类型、时间、标签和内容哈希。
2. 本地路径先通过真实根校验；网页只接受允许的 `http` 或 `https` 协议。
3. 复用对应办公技能抽取 docx、xlsx、pptx、pdf 文本；md、txt、html 使用受控抽取器。
4. 依次执行清洗、分段、向量化和索引。每个阶段保留状态；部分失败不能伪装成完整入库。
5. 用内容哈希去重。内容更新时建立新修订关系，不静默覆盖来源记录。

## 检索

- 查询前用 `kb_status` 了解库规模、索引状态和嵌入供给方。
- 默认采用全文与向量混合召回，并由 RRF 合并；用户明确要求时可选择全文或语义检索。
- 返回相关 chunk、来源、定位信息和高亮。不要只给脱离上下文的片段。
- 对多个来源的冲突进行标注，不自行抹平差异；时间敏感信息优先展示日期与修订。
- 检索不到足够证据时直说，并建议添加资料、调整查询或使用外部采集。

## 产出与引用

区分来源明确支持的陈述、由多个来源推导的结论和你的建议。生成文档时保留引用清单；新产物只有在用户要求或任务流程明确包含回收入库时才添加到知识库。
