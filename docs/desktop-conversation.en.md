# Desktop streaming conversations

The conversation view starts and stops Runs through the narrow sandbox-preload surface. Renderer can submit only a `sessionId`, user text, and an interactively selected session mode. Electron main obtains provider, model, protocol, reasoning level, and API key from validated settings and operating-system-encrypted storage.

Main converts the request's explicit `plan`, `work`, or `full_access` mode into a versioned `runtime.run.start` JSONL message. The independent runtime validates provider/model ownership, protocol, and reasoning level against the model catalog, then calls the production OpenAI-compatible streaming client. Tool declarations are generated from the configuration registry in Chat Completions or Responses format, and one structured tool call is accepted per reasoning cycle. Every committed model, action, approval, and terminal Run event returns under the same request ID. Renderer appends model text with `textContent`; it never interprets model output as HTML.

The input card keeps Plan, Work, and Full Access controls visible and disables mode changes while a Run is active. Full Access requires a separate confirmation that explains the high-risk effect, applies only to the current session, and resets to the saved default when a new session starts.

While a Run is active, the send control changes to the design system's SVG stop icon. After `run.created`, the user can send a cancellation request containing the exact Run ID. Runtime aborts only that active Run, propagates its `AbortSignal` to the network stream, and then persists the terminal state in SQLite. Cancellation and the long-running start request are processed concurrently, so the model call cannot block the stop command.

Ordinary RPC calls retain a short timeout, while model Runs use the separate long timeout in `desktop-config.data.json`. The v1 runtime executes one Run at a time to keep event ownership unambiguous. The `prepare` stage restores same-session history under the configured budget, while current-Run observations return to the next reason cycle with an explicit untrusted label. Filesystem, search, terminal, web, and knowledge tools pass strict input schemas, policy evaluation, the action ledger, configured byte limits, and result verification. Knowledge hits appear as both in-conversation citations and read-only source cards in the right panel.
