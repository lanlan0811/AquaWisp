# 工具注册表与权限求值

`packages/tools/src/tool-catalog.data.json` 是 M3 工具与安全策略的数据源。它声明规范工具 ID、模型安全名称、版本、副作用、风险等级、自然语言描述、严格 JSON 输入 schema、三种运行模式的自动放行与拒绝风险，以及必须审批的边界范围。runtime 根据协议把同一份数据转换成 Chat Completions 或 Responses 工具声明，不维护第二份硬编码清单。

`ToolPolicyEvaluator` 固定按以下顺序求值：动作契约和工具注册表 → 显式拒绝 → 项目拒绝 → 工作区/秘密/平台边界识别 → 模式风险硬拒绝 → 边界审批或模式默认。显式拒绝不会被覆盖，`plan` 对中高风险的硬拒绝也不能通过边界审批绕过。

`plan` 仅自动放行低风险操作；`work` 自动放行低、中风险的工作区操作；越出工作区、涉及秘密或平台边界的动作始终返回结构化审批请求。每个请求含 action、目标、风险原因、时间与可审计审批 ID。

桌面审批通过版本化 runtime RPC 恢复仍停在 authorize 的 Run。审批 ID、Run ID 与 action ID 必须完整匹配；允许决定先写入 `approval.resolved` 再推进账本，拒绝决定记录 `action.denied` 且不派发。会话内授权按操作、目标、风险原因和影响范围精确匹配，runtime 重启后保守失效。详见 [桌面端审批与会话授权](desktop-approvals.md)。

文件工具只访问 `runtime-host.data.json` 声明的独立工作区子目录，与事件库、知识库和上下文工件隔离，并使用该目录的真实根路径校验输入。读取返回内容 SHA-256 revision；写入和编辑必须携带该 revision，且写入会在目标同一目录内完成原子替换。符号链接或 junction 指向工作区外时会被拒绝，审批也不会放宽这个工具能力边界。

终端工具只接收可执行文件与参数数组，使用 `shell: false` 启动进程；命令行不经字符串拼接。cwd 必须解析到工作区真实根内，stdout/stderr 都有上限，超时后会终止子进程并在结构化结果中标记。由于任意进程属于平台边界，生产策略始终要求精确审批；取消 Run 会终止正在执行的子进程。

`web_fetch` 仅请求配置白名单中的 URL 协议，并对最终 URL 再次校验。响应体按字节截断，结果始终带有 `untrusted: true`，调用方不得把网页正文当作策略、权限或系统指令。

`runtime-host.data.json` 统一声明工具参数、文件、终端输出、网页正文和聚合观察的字节上限。超过聚合观察上限时，runtime 返回带 `truncated`、原始字节数和有界预览的结构化结果；模型工具参数超限则在形成动作前失败。工具观察只作为不可信用户数据进入下一轮 reason，不能修改注册表、权限或审批。
